# Synera: Synergy Auto-Arena

**Synera: Synergy Auto-Arena** 是一款使用 **C++17**、**Qt6** 和 **CMake** 开发的轻量级单人 PvE 自走棋游戏。

本项目主要探索如何使用面向对象程序设计组织一个自走棋游戏系统，包括统一单位模型、多态英雄技能、网格战斗、BFS 寻路、装备系统、羁绊效果，以及基于 JSON 的存档与读档支持。

## 项目概述

Synera 遵循自走棋游戏的核心循环：

1. **准备阶段**  
   玩家可以从商店购买单位，管理金币，将单位放置到棋盘上，装备物品，并调整阵型。

2. **战斗阶段**  
   玩家单位和敌方单位会自动寻找目标，在棋盘上移动、攻击、获得法力值并释放技能。

3. **结算阶段**  
   游戏会结算本回合结果，发放奖励，处理装备掉落，更新玩家生命值，并进入下一回合。

本游戏实现为单人 PvE 体验。敌方阵容由一个简单的准备阶段智能体控制，用于执行购买、升级、部署和阵型决策。

## 功能特性

- 8 × 8 网格战场
- 玩家棋盘区域与敌方棋盘区域
- 用于存放未上场单位的备战区系统
- 支持拖拽式单位放置
- 玩家单位和敌方单位共用统一的 `Unit` 模型
- 基于继承和虚函数技能分派的面向对象英雄系统
- 12 个具有不同技能效果的英雄类
- 准备 / 战斗 / 结算阶段循环
- 单位有限状态机：`Idle`、`Moving`、`Attacking`、`Casting`、`Dead`
- 自动目标选择
- 基于 BFS 的寻路，并支持碰撞规避
- 普通攻击、法力值获取、技能释放和死亡处理
- 商店、金币、刷新、购买和人口系统
- 基于起源标签和职业标签的羁绊系统
- 基于三个相同单位合成的升星系统
- 装备背包、装备穿戴和装备合成
- 弹道效果和简单战斗视觉效果
- JSON 存档与读档系统
- 基于 Qt Graphics View 的图形界面

## 核心设计

### 统一单位模型

玩家单位和敌方单位使用同一套 `Unit` 类层次结构，而不是被实现为两套独立的类型系统。

单位的归属由 `Owner` 字段表示：

```cpp
Owner::PlayerCtrl
Owner::EnemyCtrl
```

羁绊标签通过 `origin` 和 `role` 字段单独表示。这样可以让战斗归属和羁绊计算彼此独立，避免把“属于哪一方”和“拥有什么羁绊”混在一起。

### 面向对象英雄系统

基类 `Unit` 定义了通用属性，例如：

- 生命值 / 最大生命值
- 攻击力
- 攻击范围
- 法力值 / 最大法力值
- 攻击速度
- 护甲和魔法抗性
- 星级
- 装备
- 单位归属
- 当前战斗状态
- 起源标签和职业标签

它还定义了虚函数技能接口：

```cpp
virtual void castSkill(Game* game, Unit* target);
```

具体英雄类继承自 `Unit`，并重写该函数以实现不同的技能效果。

因此，战斗系统可以通过基类指针调用：

```cpp
caster->castSkill(this, target);
```

在运行时，C++ 的动态绑定机制会自动调用对应英雄自己的技能实现。

这一设计体现了高级程序设计课程中面向对象程序设计的核心思想：继承、重写、多态和动态绑定。

## 战斗系统

### 阶段循环

游戏循环围绕三个主要阶段组织：

```text
准备阶段 → 战斗阶段 → 结算阶段 → 准备阶段
```

在准备阶段，玩家可以：

- 购买单位
- 刷新商店
- 穿戴装备
- 升级等级
- 调整棋盘站位

在战斗阶段，单位由战斗系统自动控制，会执行：

- 自动选择目标
- 向目标移动
- 普通攻击
- 获得法力值
- 释放技能
- 死亡移除

当一方被击败后，游戏进入结算逻辑，更新金币和生命值，处理物品掉落，推进回合，并恢复准备阶段棋盘。

### 单位状态机

每个战斗单位都由一个有限状态机控制：

| 状态 | 含义 |
|---|---|
| `Idle` | 等待、眩晕、冷却中或没有合法行动 |
| `Moving` | 向目标移动 |
| `Attacking` | 执行普通攻击 |
| `Casting` | 释放技能 |
| `Dead` | 单位已经死亡并将被移除 |

战斗 tick 会按照优先级顺序检查单位状态：

1. 死亡检查
2. 眩晕检查
3. 冷却检查
4. 技能释放检查
5. 攻击范围检查
6. 移动检查

这种结构使战斗行为更加可预测，也避免将移动、攻击和技能逻辑混杂在一个不可控的流程中。

## 寻路系统

Synera 使用 BFS 在网格上移动单位。

寻路函数从单位当前位置开始搜索，寻找一个位于目标攻击范围内的可达格子。它会避开非法格子和被占用格子，在搜索过程中记录父节点，并让单位沿恢复出的路径移动一步。

相比简单贪心移动，BFS 能更可靠地处理阻挡和基础绕路情况。

### 简化 BFS 逻辑

1. 从单位当前所在的网格位置开始。
2. 将起点格子加入队列。
3. 逐层访问相邻格子。
4. 忽略棋盘外格子和已被占用的格子。
5. 记录每个格子的父节点。
6. 当找到一个处于攻击范围内的可达格子时停止搜索。
7. 通过父节点记录恢复路径。
8. 沿路径移动一步。

## 目标选择

单位会在战斗中自动选择敌人。目标选择逻辑会考虑以下因素：

- 到目标的距离
- 当前生命值比例
- 攻击能力
- 该单位是远程单位还是近战单位
- 敌人当前是否正在攻击该单位

这使单位具备基础的威胁感知目标选择行为，而不是永远只攻击最近目标。

## 经济与商店系统

游戏包含一个基础经济系统：

- 初始金币
- 回合奖励
- 商店刷新费用
- 单位购买费用
- 等级升级费用
- 基于玩家等级的人口上限
- 基于当前金币数量的利息奖励
- 连败补偿

商店会从单位池中随机提供可购买英雄。如果备战区有空位，购买的单位会被放入备战区。

## 羁绊系统

单位拥有起源标签和职业标签。当多个拥有相同标签的单位被部署时，对应羁绊效果会被激活。

已实现的羁绊类型包括属性加成和护盾类机制，例如：

- 生命值加成
- 攻击速度加成
- 护甲与魔法抗性加成
- 攻击力加成
- 护盾效果

羁绊效果会在战斗准备阶段应用到战斗副本上，从而保持玩家原始准备棋盘状态稳定不变。

## 升星系统

本项目实现了三合一升星系统。

当玩家拥有至少三个名称和星级都相同的单位时，游戏会将它们合成为一个更高星级单位。升星后的单位会获得更高属性，例如更多生命值和攻击力。

合成系统会同时检查棋盘和备战区。

## 装备系统

游戏包含装备背包和装备穿戴系统。

单位可以穿戴装备，装备容量取决于星级。装备系统同时支持基础装备属性加成和合成装备。

示例装备效果包括：

- 攻击力加成
- 攻击速度加成
- 护甲加成
- 魔法抗性加成
- 生命值加成
- 法力值相关效果
- 暴击率加成

游戏还支持若干装备组合，可以合成带有额外被动效果的更强装备。

## 存档与读档

游戏状态可以保存到 JSON 文件，也可以从 JSON 文件读取。

存档系统会记录以下信息：

- 游戏阶段
- 玩家状态
- 敌方状态
- 商店槽位
- 装备背包
- 单位属性
- 单位位置
- 单位归属
- 单位星级
- 单位装备
- 战斗相关临时状态

读档会重建游戏状态，并相应刷新图形界面。

## 构建与运行

### 推荐方式：CLion

1. 安装 Qt6。
2. 在 CLion 中打开项目根目录。
3. 让 CLion 加载 CMake 项目。
4. 选择 `Synera_Starter` 构建目标。
5. 点击 `Build` 进行构建。
6. 点击 `Run` 运行程序。

### 命令行方式

命令行构建可能需要通过 `CMAKE_PREFIX_PATH` 手动设置 Qt6 路径。

示例：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/Qt/6.x.x/macos
cmake --build build
```

具体 Qt 路径取决于本地安装位置。

## 玩法说明

1. 启动游戏。
2. 从商店购买单位。
3. 将单位从备战区拖拽到玩家侧棋盘。
4. 如果有装备，可以给单位穿戴装备。
5. 如果金币足够，可以升级等级。
6. 开始战斗。
7. 观察单位自动移动、攻击、获得法力值并释放技能。
8. 战斗结束后领取奖励，并进入下一回合。
9. 需要时可以保存或读取游戏。

## 当前局限

- 当前视觉风格较为简单，主要使用基础图形和文字标签。
- 战斗平衡性仍需要更系统的测试。
- BFS 可以处理普通阻挡情况，但在极端拥堵时可能会出现等待。
- 敌方准备逻辑基于启发式规则，而不是基于搜索算法。
- 目前尚未加入音效和背景音乐。
- 本项目主要在 macOS、CLion 和 Qt6 环境下开发与测试。

## 开发说明

本项目从一个基于 Qt 的初始框架出发，扩展为一个较完整的自走棋原型。

主要开发重点不是视觉美化，而是系统设计：

- 清晰的对象所有权
- 可维护的单位与英雄类层次结构
- 技能的虚函数动态分派
- 结构化的战斗状态转换
- 基于网格的移动与碰撞处理
- 可序列化的游戏状态
