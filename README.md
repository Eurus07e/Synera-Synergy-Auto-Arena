## 3. 核心类和数据结构

### `Unit`

`Unit` 是所有棋子的基础类，保存 `id`、稳定英雄类型、名字、位置、星级、费用、生命值、攻击力、攻击距离、法力值、法术强度、护甲、魔抗、攻速、暴击率、阵营归属、前后排定位、羁绊以及穿戴装备等信息。稳定英雄类型使 JSON 读档重建出的单位仍可由 `Game` 执行正确技能。

具体英雄类继承 `Unit` 并保留卡面参数；战斗中的技能分发统一由 `Game` 处理，以便技能临时状态、战斗副本和存档使用相同数据来源。

### `Board`

`Board` 是 8x8 棋盘占位表，内部用 `QVector<Unit*>` 保存每个格子的单位指针，并用 `QHash<Unit*, QPoint>` 反查单位位置。主要负责：

- 判断棋盘坐标是否合法。
- 判断某格是否有单位。
- 添加、移除单位。
- 判断是否在玩家半场。
- 清空棋盘状态。

### `Bench`

`Bench` 是 8 格备战席。玩家和敌方各有一个 `Bench`。主要负责：

- 找空位放入单位。
- 指定槽位放入单位。
- 交换两个槽位的单位。
- 查询、删除单位。
- 判断槽位是否合法。

### `Player`

`Player` 保存玩家局内状态：

- 血量：初始 100。
- 金币：玩家初始 6，敌方初始 3。
- 等级：初始 1，人口上限等于等级。
- 升级进度：点击等级按钮会调用 `buyLevelProgress()`，花费金币购买升级进度。

等级规则当前为：等级到达阈值后通过 `tryApplyLevelUp()` 连续结算升级，满级后不再继续升级。每轮结算还包含基础金币/经验、胜者奖励、连败补偿和金币利息。

### `Game`

`Game` 是当前最重要的协调类。它同时持有逻辑数据和 Qt 场景对象：

- `Board m_board`
- `Bench m_bench`
- `Bench m_enemyBench`
- `Player m_player`
- `Player m_enemy`
- `QGraphicsScene* m_scene`
- 所有 `GridItem`、bench 槽位、`UnitItem`、商店槽位、出售区域等。

当前 `Game` 负责：

- 构建棋盘、敌方 bench、玩家 bench、Sell 区和装备栏。
- 处理拖拽开始、拖拽移动、拖拽释放。
- 判断棋盘/bench 的落点是否合法。
- 支持棋盘单位互换、bench 单位互换、棋盘和 bench 之间互换。
- 随机刷新商店。
- 购买商店单位。
- 购买后尝试合成。
- 出售单位并返钱。
- 创建战斗副本、自动普攻、暴击、弹道表现、战斗结算并恢复准备阶段阵容。
- 管理敌方 agent 的购买、刷新、出售、升级和前后排横向布阵。
- 处理装备掉落、拖拽穿戴、成装组合与被动效果。
- 使用 JSON 序列化/反序列化完整保存和恢复游戏状态。
- 依据法力值释放技能、维护护盾/冰冷/眩晕/强化普攻等战斗临时状态，并在战斗副本上施加羁绊。
- Reset 新一局：清空旧单位，随机给一个 1 费英雄放入玩家 bench。

### `GameWindow`

`GameWindow` 是主界面：

- 左侧是 `QGraphicsView`，展示棋盘、bench、单位和 Sell 区。
- 右侧是常驻商店面板，展示两个随机英雄卡牌。
- 底部是状态栏，展示 HP、Gold、等级进度、回合。
- 点击商店卡牌购买英雄。
- 点击 Refresh 花 4 金币刷新商店。
- 点击等级状态按钮购买升级进度。
- 右键或辅助点击单位可以弹出角色详情卡，详情卡里有完整参数、羁绊、技能说明和出售按钮。
- 左上角装备图谱按钮展示合成关系，右键装备节点显示具体效果。
- 顶栏展示玩家当前已激活羁绊；单位详情卡可展示战斗中的护盾、冰冷和眩晕状态。
- 底部存档/读取按钮通过固定单存档槽的 JSON 文件保存并恢复当前对局。

## 4. 当前已完成的功能模块

### 棋盘与备战席

- 玩家棋盘为六边形 8x8。
- 上方显示敌方 bench，下方显示玩家 bench。
- 一开始生产棋子不再直接放到棋盘，而是放入玩家 bench。
- Reset 时会清空棋盘、bench、单位图元和商店状态，然后随机发一个 1 费英雄到玩家 bench。

### 拖拽和换位

- 单位可以从 bench 拖到棋盘，也可以从棋盘拖回 bench。
- 拖到空棋盘格时执行放置。
- 拖到已有棋子的棋盘格时执行互换。
- bench 内部也可以互换位置。
- bench 与棋盘之间可以互换。
- 当前人口上限等于玩家等级，部署到棋盘的玩家单位数量不能超过等级。

### 商店

- 商店常驻在右侧，不需要点按钮打开。
- 商店一次显示 2 个英雄。
- 商店池使用已经实现的真实英雄，包含费用、星级、基础属性、羁绊和技能描述。
- 点击整张商店卡牌即可购买。
- 买英雄时检查金币是否足够、bench 是否有空位。
- Refresh 按钮花 4 金币重新随机两个英雄。
- 商店参数使用英文全称，不使用 AR/MR/AS 这类缩写。
- 英雄名后显示中文名，羁绊后显示中文翻译。

### 合成

- 购买或新增单位后会检查同名、同星级的单位。
- 如果场上和 bench 合计有 3 个同类同星单位，则合成为更高一星。
- 合成优先保留棋盘上的单位；如果没有棋盘单位，则保留 bench 中的第一个候选。
- 被消耗的两个单位会从棋盘/bench/单位列表/图形 item 中彻底移除。
- 合成后会更新保留单位的星级和参数，并同步图形界面。
- 需要注意：后续如果加入战斗中临时属性，合成时要区分基础属性和战斗临时状态。

### 出售

- `sellUnitById(int unitId)` 是图形界面对出售逻辑的入口。
- 出售会确认单位属于玩家，避免卖掉敌方单位。
- 出售成功后移除单位、清理图形 item，并按当前费用返还金币。
- 右键详情卡里有出售按钮。
- 棋盘左下方有 Sell 格子，单位拖到该格子上会触发出售。

### 状态栏和等级

- 底部状态栏显示 HP、Gold、Lv 进度、Round。
- Gold 显示为完整英文。
- 等级按钮可点击，点击后调用 `buyLevelProgress()`。
- 等级进度显示为 `当前进度 / 当前等级所需进度`，满级时显示 MAX。

### 战斗与敌方 Agent

- 玩家点击开始战斗后，`Game` 会为场上真实单位创建战斗副本；战斗结束后删除副本并恢复准备阶段的真实阵容和原位置。
- 单位依据攻击距离和攻速自动进行普通攻击，当前普通攻击支持暴击判定，并以子弹/轨迹图元表现攻击方向。
- 普攻命中会获得法力；法力达到上限时下一次行动释放技能。护盾先吸收伤害，冰冷降低攻速，眩晕会阻止行动。
- 全部 12 名英雄均已接入核心可玩技能：嘉文/兰博/洛里斯/瑟庄妮提供护盾或控制，娑娜/科加斯提供回复，艾希施加冰冷，赵信与亚索处理近战爆发，阿狸提供范围伤害，烬与金克丝使用强化普攻机制。
- 本阶段简化了高级卡面细节：未实现洛里斯击退/嘲讽、科加斯跨战斗永久成长、阿狸第三次强化等扩展机制。
- 索敌使用距离主导的威胁评分：距离、目标输出能力、当前生命和射程共同决定攻击目标；分数相同时优先生命值更高、位置更靠左且更靠下的目标。
- 一方场上战斗单位全部死亡后自动结算；输方根据赢家剩余单位数量扣血，双方获得随轮次增加的金币和经验，赢家额外获得奖励。
- 已加入利息与连败补偿，避免落后一方完全失去追赶机会。
- enemy 拥有自己的金币、等级、商店和 bench；准备阶段自动购买、刷新、出售弱牌及部署单位。
- enemy 前排优先在敌方交战线、后排优先在敌方最后一排横向排列；每排从中央向两侧展开，减少互相阻挡并保持接战位置合理。

### 羁绊系统

### 装备系统

- 玩家战斗胜利后有 30% 概率掉落一件基础装备，装备显示于左侧单列装备栏，可拖拽到玩家单位身上。

## 5. 算法描述

### 六边形坐标映射

棋盘使用错列六边形。`gridToWorld(row, col)` 根据行列计算图形中心点：

- 列间距约为 `radius * sqrt(3)`。
- 偶数行增加半个列间距的水平偏移。
- 行间距使用固定的 `m_rowSpacing`。

`worldToGrid(scenePos)` 会遍历所有格子中心，找到距离鼠标位置最近的格子。如果最近距离仍超过半径，就认为鼠标不在有效格子内。

### 拖拽落点判断

拖拽释放时，`Game::handleDropCommand()` 会按优先级判断：

1. 是否拖到 Sell 区，是则出售。
2. 是否拖到玩家 bench，是则尝试放入或换位。
3. 是否拖到棋盘，是则尝试放置或换位。
4. 都不满足则回到原位。

真正修改状态的函数集中在 `applyDrop()`、`applyBenchDrop()`、`swapBoardUnits()`、`swapBenchUnits()` 等函数中，图形位置由 `syncFromState()` 统一刷新。

拖拽合法性还会检查单位归属：玩家只能拖动自己的真实单位，敌方单位和战斗副本无法被拖入玩家棋盘或备战席。

### 商店随机

商店池定义在 `game.cpp` 的匿名命名空间中。`rollShop()` 从完整商店池中随机抽取 2 个 `ShopSlot`，刷新右侧商店 UI。

开局随机英雄使用 `randomCostOneShopSlot()`，先过滤出 1 费英雄，再随机选择一个，保证每局开始只送 1 费棋子。

### 三合一升星

合成逻辑围绕 `tryMergeUnit(Unit* unit)`：

1. 用 `findMergeCandidates()` 找到同名、同星级、同玩家归属的候选。
2. 数量不足 3 则不合成。
3. 优先选择棋盘上的单位作为保留单位，否则选择候选列表第一个。
4. 删除另外两个单位。
5. 提升保留单位星级，并调整对应参数。
6. 再次检查是否可以连续合成。

未来如果要支持 3 星上限，需要在合成入口明确判断星级上限，避免继续合成到不合理状态。

### 出售区域判断

Sell 区也是 `QGraphicsPathItem`。拖拽时通过 `m_sellZoneItem->path().contains(scenePos)` 判断鼠标是否落在出售区域。当前 Sell 区已经改为和 bench 相同大小的方形格子，并放在玩家 bench 左侧。

### 战斗副本与结算

`setupCombatCopies()` 在开战时保存真实单位的位置并创建战斗副本，所有移动、扣血和装备战斗被动只作用在副本上。`finishCombat()` 结算胜负、经济和伤害后，调用 `cleanupCombatCopies()` 删除副本，再由 `restorePreparationBoard()` 恢复原阵容。这样死亡不会永久删除玩家已经购买的单位。

### 智能锁敌评分

`targetThreatScore()` 对每个可攻击的敌方单位计算威胁分数。距离平方乘以较大的负权重，使接近攻击者的敌人仍然占主要优先级；目标攻击力、攻速和暴击率形成输出威胁，当前生命值与攻击距离作为附加威胁。`findNearestEnemy()` 选择最高分目标；同分时按高生命、从左向右、从下到上的顺序稳定决策。

### 装备掉落与穿戴

`tryDropBasicEquipment()` 在玩家胜利结算时按 30% 概率随机产生基础装备。`equipInventoryItem()` 检查目标是否为玩家真实单位和装备容量，之后应用属性；若新散件和某件已穿装备满足配方，则将装备标识替换为成装并启用其被动。战斗开始时，装备与已经应用的属性会复制到战斗副本。

### JSON 序列化与反序列化

`saveGame()` 将 `Player`、商店、装备库存和所有单位状态转换为 `QJsonObject` / `QJsonArray`，再通过 `QSaveFile` 原子写入文件。`loadGame()` 校验版本后清空当前游戏对象，恢复玩家状态并逐个重建单位与图元；存档处于战斗阶段时重新启动战斗计时器。

## 6. 辅助函数说明

以下函数属于全局或局部辅助逻辑，最终 README 可以继续补全：

- `originToText()` / `roleToText()`：把羁绊枚举转为英文 + 中文显示。
- `heroLocalizedName()`：把英雄英文名转为中文名。
- `shopStatsText()`：生成商店卡牌的参数 HTML。
- `unitStatsText()`：生成右键详情卡的参数 HTML。
- `skillText()` / `unitSkillText()`：把技能名和技能正文拆开显示。
- `gridToWorld()` / `worldToGrid()`：棋盘逻辑坐标与场景坐标互转。
- `benchSlotRect()` / `benchSlotCenter()`：计算 bench 槽位矩形和中心点。
- `findBenchSlot()`：根据鼠标场景坐标查找当前落在哪个 bench 槽位。
- `removeUnitCompletely()`：从棋盘、bench、图形 item、单位列表中彻底删除单位。
- `tryDropBasicEquipment()` / `applyEquipmentStats()`：生成装备掉落并把装备属性应用到单位。
- `setupCombatCopies()` / `restorePreparationBoard()`：在战斗副本和准备阶段真实单位之间切换。
- `runEnemyPrepareAgent()` / `arrangeEnemyFormation()`：执行敌方准备操作并按前后排整理站位。
- `saveGame()` / `loadGame()`：将对局状态写入 JSON 并恢复全部可继续运行的状态。

## 8. AI 使用说明

本项目允许使用 AI 辅助，但需要完全理解和掌控代码。当前 AI 辅助主要用于以下方面：

### 项目规划

AI 协助把 PA 需求拆分为小模块：棋盘与 bench、拖拽、人口等级、商店、购买、合成、出售、战斗、敌方 agent、装备、存档和 UI 展示。开发过程中先实现最小可运行功能，再逐步补交互与边界情况。

### 核心代码解释

AI 对以下模块进行了较多解释和辅助实现，验收时应重点能用自己的话说明：

1. `Game` 的拖拽和状态同步逻辑  
   需要说明为什么 `UnitItem` 不直接修改 `Board`，而是通过 signal 把操作交给 `Game`，再由 `syncFromState()` 统一刷新图形。

2. 商店、购买、合成、出售逻辑  
   需要说明 `ShopSlot` 为什么保存英雄类型和参数，购买时如何创建真实 `Unit`，合成时如何跨棋盘和 bench 查找候选，出售时如何从所有容器中删除单位。

3. 战斗副本、敌方 agent 与结算逻辑  
   需要说明为什么战斗时不直接修改真实阵容，enemy 如何在准备阶段操作经济和阵型，以及回合奖励、利息、连败补偿如何发放。

4. 装备与存档逻辑  
   需要说明装备库存、穿戴/合成/被动如何落到 `Unit` 和战斗副本上，以及 JSON 读档为何要先清理旧对象再重建占位关系。

### AI 生成痕迹与人工掌控

- 多处代码旁已经加入少量中文注释，解释功能和运作原理。
- AI 曾协助处理 Clang-Tidy 提示、命名规范、UI 布局、Qt 富文本展示、战斗/装备逻辑与 JSON 存档实现。
- 所有 AI 生成或修改的逻辑都需要最终由本人检查、运行、解释。
- 如果验收时发现某段代码无法解释，应视为高风险部分，需要重写或补充注释。
